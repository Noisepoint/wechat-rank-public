# 公众号文章热度监测工具 - 产品需求文档 (PRD)

> 本文档面向产品和业务，描述"做什么"和"为什么"。

---

## 一、产品概述

### 1.1 产品定位
AI领域公众号文章热度监测工具，帮助内容创作者快速发现热门选题。

### 1.2 核心目标
- 监测AI领域公众号的文章热度数据
- 发现具有爆发潜力的选题（话题驱动而非粉丝驱动）
- 提供选题分析报告辅助内容决策

### 1.3 使用场景
- 个人使用，无需登录系统
- 每周写2篇公众号文章，需要高效找到优质选题

## 二、数据架构

### 2.1 数据来源
| 数据源 | 用途 | 说明（脱敏版） |
|--------|------|----------------|
| wechat2rss 私有部署 | 获取文章列表、正文内容 | 需自建/付费服务 |
| 极致了API Pro版 | 获取阅读/点赞/在看/转发/收藏/评论 | 按调用次数计费 |

**wechat2rss私有部署特点：**
- 支持任意公众号，不限数量
- 上游侧平均约6小时更新一次（受微信风控/登录状态影响）
- **以本工具后台为准添加/删除监测公众号**：工具会自动调用 wechat2rss 订阅；一般不需要在 wechat2rss 后台手动维护列表
- 若 wechat2rss 微信账号风控/登录失效，将无法采集新文章；工具侧会提示上游状态并引导排查
- 购买/部署方式请参考 wechat2rss 官方说明（本文档为脱敏版，不放具体链接）

### 2.2 采集数据字段
**文章级数据：**
- 文章标题、链接、发布时间、正文内容
- 阅读量、点赞数、在看数、评论数、收藏数

**账号级数据：**
- 公众号名称、ID、头像
- 近14天篇均阅读量（用于计算超常指数）
- 历史发文频率

### 2.3 更新频率
- 每日更新一次（线上由定时任务触发）
- 数据采集时间、邮件推送时间：线上触发时间以 Vercel `vercel.json` 为准（通常按 UTC 执行；若要按北京时间运行需换算）。设置页里的时间用于记录/对齐，避免误解
- 本地开发环境不会自动定时执行：可在设置页使用“立即采集全部 / 立即发送测试邮件”验证链路

### 2.4 数据采集策略（增量采集 + 周期更新）
**核心原则：新文章入库，7天内旧文章每日更新数据**

**“近7天”口径（自然日，口径C）：**
- 起点：从“今天往前推7天”的 **00:00** 开始（以服务器时区为准）
- 终点：当前时刻
- 目的：避免“按7×24小时滚动窗口”导致边界日（例如 1/29 上午）的文章被漏掉

1. **首次添加账号**：先抓取该账号**近7天（自然日口径C，含今天）**历史文章数据入库；验证稳定后再扩到14天
2. **每日新文章采集**：抓取新发布的文章并存储（账号不会停止更新）
3. **每日旧文章更新**：仅刷新**发布在最近7天内**文章的互动数据（保证周榜数据准确）
4. **篇均阅读量计算**：从数据库查询近14天数据计算，无需重复调API
5. **防漏补机制**：每次采集都会回看该账号**最近7天**的文章列表，对库中缺失文章做补齐，避免出现“显示新增0但实际有漏文”

**采集流程：**
1. 调用 wechat2rss `/api/query` 获取新文章列表和正文
2. 调用极致了API Pro版获取每篇文章的互动数据
3. 计算热度指标并存入数据库
4. 查询数据库中7天内的旧文章，逐一调用API更新互动数据

**数据更新说明：**
- 7天内的文章：每日采集时自动更新最新互动数据
- 超过7天的文章：文章仍保留在库里，但互动数据不再刷新（节省API成本/降低风控概率）
- “7天窗口”指互动数据刷新范围，不代表账号会停止采集新文章
- 月榜数据：超过7天的文章显示的是最后一次采集时的数据

### 2.5 成本预算
（脱敏版，不披露具体金额）

- 成本主要由两部分组成：`wechat2rss` 服务费用 + `极致了API` 按量调用费用。
- 实际费用与监测账号数量、采集频率、初始化回溯天数、互动数据更新窗口等有关。
- 建议上线前先用少量账号试跑 1-2 天，结合数据看板里的 API 调用量估算月成本。

## 三、热度算法设计

### 3.1 设计原则
- **可配置化**：权重参数可在设置页调整，无需改代码
- **完整数据采集**：存储所有原始数据，算法可随时重算

### 3.2 算法方案（可配置，后期可调优）

```
选题热度 = 超常指数 × 互动质量分
```

**超常指数（发现话题驱动的爆文）：**
```
超常指数 = 本文阅读量 ÷ 该账号近14天篇均阅读
```
- 核心逻辑：小号平时500阅读，这篇5000 → 超常指数=10，说明是话题本身在驱动传播

**互动质量分（参考行业权重）：**
```
互动质量分 = (点赞×W1 + 在看×W2 + 评论×W3 + 收藏×W4 + 转发×W5) ÷ 阅读量 × 1000
```
- 默认权重：W1=1, W2=2, W3=5, W4=3, W5=2（可配置）
- 点赞：基础认可
- 在看：愿意传播
- 转发：更强传播信号
- 评论：深度参与（权重最高）
- 收藏：内容价值认可

**入榜门槛（绝对值过滤）：**
- 阅读量 ≥ 1000（可配置）

### 3.3 榜单类型
| 榜单 | 排序依据 | 用途 |
|------|----------|------|
| 超常发挥榜 | 超常指数 | 找话题驱动的爆文 |
| 互动质量榜 | 互动质量分 | 找读者反馈好的文章 |
| 综合热度榜 | 超常指数×互动分 | 两者兼顾 |

### 3.4 时间维度
- 日榜：过去24小时
- 周榜：近7天（自然日口径C：起点=今天往前推7天00:00）
- 月榜：近30天

## 四、功能模块

### 4.1 热榜首页
**核心功能：**
- 展示日榜/周榜/月榜切换
- 展示超常榜/互动榜/综合榜切换
- 列表展示：排名、标题、账号、阅读量、互动数据、热度分、发布时间

**列表交互：**
- 点击标题 → 站内弹窗预览正文
- 支持升序/倒序排序
- 支持导出Excel/CSV
- 支持关键词/账号名搜索

### 4.2 公众号管理页
**功能：**
- 查看已监测的公众号列表
- 添加新公众号（只需粘贴任意一篇文章链接，系统自动识别公众号名称）
- 删除公众号
- 与 wechat2rss 同步：**以本工具后台为准**添加/删除账号，工具自动同步到 wechat2rss；同时提供“同步刷新”作为对账兜底（从 wechat2rss 拉回订阅列表补齐/校验差异）

### 4.3 分类筛选

**AI细分领域（按应用场景）：**
- AI写作
- AI绘画/设计
- AI编程
- AI办公/效率
- AI视频/音频
- AI对话/聊天
- 其他

**文章类型：**
- 教程/攻略
- 工具推荐/测评
- 行业资讯/新闻
- 观点评论/分析
- 案例拆解

**分类方式：**
- 第一版：关键词规则自动匹配
- 后续迭代：可接入LLM自动分类
- 支持手动修正分类

### 4.4 标题特征分析页
**分析范围：**
- 只分析入榜文章（符合阅读量门槛），与热榜数据同步

**分析维度：**
- 高频关键词：热文标题中出现最多的词
- 标题套路模式：如"X个必备"、"我用XX做了XX"、"刚刚，XX发布了"等

**展示形式：**
- 关键词词云
- 套路模式排行榜
- 支持按时间周期筛选（日/周/月）

### 4.5 选题收藏夹
**功能：**
- 收藏感兴趣的文章
- 添加备注说明
- 列表查看已收藏文章

### 4.6 选题分析报告页
**报告内容：**
| 模块 | 说明 |
|------|------|
| 热门选题概览 | Top热文榜单 + 各分类热度分布 |
| 标题关键词分析 | 高频词 + 新兴词 |
| 标题套路分析 | 热门套路排行 |
| 趋势变化 | 对比上一周期的热度变化 |
| 选题建议 | 基于数据规则自动生成（后期可接AI） |
| 竞品对比 | 各账号表现对比 |

**报告周期：**
- 日报：每日生成
- 周报：每周生成

**输出形式：**
- 网页查看
- 邮件推送

### 4.7 数据统计看板
**展示内容：**
- 今日采集文章数
- 各分类热度趋势图
- 高频关键词词云
- API用量监控：已调用次数、已花费金额、剩余余额（避免超预算）

### 4.8 设置页
**可配置项：**
- 邮件推送时间
- 推送邮箱地址
- 热度算法权重参数（W1、W2、W3、W4、W5）
- 入榜阅读量门槛
- 分类标签管理
- 数据采集时间
- 上游状态检查（wechat2rss）
- 手动立即采集入口（立即采集全部，用于“现在就拉一次”）

## 七、验证方式

### 7.1 数据采集验证
- 检查 wechat2rss 是否正常返回文章列表
- 检查极致了API是否正常返回阅读/点赞数据
- 检查 wechat2rss 微信账号是否风控/登录失效（若风控则可能采集不到新文章）
- 验证数据存储是否完整

### 7.2 功能验证
- 热榜列表是否正确排序
- 分类筛选是否生效
- 搜索/导出功能是否正常
- 正文预览是否能加载

### 7.3 推送验证
- 邮件是否能正常发送
- 推送内容是否完整
- 推送时间是否准确
